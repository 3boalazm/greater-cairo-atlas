# South batch 04 adaptation

- Raw `README.md`, `entities.csv`, `facts.json`, `evidence.json`, `evidence_raw.tsv`, `status_changes.json`, `code_remap.json` and `build.py` were copied unchanged from `research/south-batch04` (merge commit `7db842a`; the folder is byte-identical to that branch).
- **31 entities** were appended to `data/seed/entities.csv`, all in the `SOUTH` sector, with zero code collisions against the existing seed. Nothing was renamed, re-sectored or re-typed.
- **70 evidence rows** were converted with `adaptResearchSeedSources` and appended; canonical refs stay in the `EV-S4-###` namespace. **95 facts** were converted and appended. Existing facts and evidence were retained unchanged; there are no deletions in this batch.
- The batch's `entities.csv` uses the **seed** column order (`code,name_ar,…`) while the adapter reads the **research** order (`entity_code,entity_type,canonical_name_ar,…`). It is converted by header name, not by position, so no column can silently shift. The raw file itself is unmodified.
- The batch's facts are not limited to its own entities: several are the evidence for the three status changes and for already-seeded SOUTH entities (`ROAD-EASTERN-DESERT`, `ROAD-AIN-SOKHNA`, `TRANSIT-BRT`, `TRANSIT-HSR-L1`, `TRANSIT-METRO-L6`, `BRIDGE-MONIB`, `ROAD-MOKATTAM-AXIS`). Those rows were supplied to the adapter for referential validation only and were **not** re-written; the only field that changes on them is the status delta below.
- **Three status changes** were applied additively: `BRIDGE-MONIB`, `ROAD-EASTERN-DESERT` and `ROAD-MOKATTAM-AXIS` move `unknown → operational`. Sector, geometry and every other field on those rows are untouched.
- Unknown statuses: the seed had 14 pre-existing `unknown` entities; the three changes above remove 3, leaving **11 pre-existing unknown**. Two entities in this batch (`LINE-HELWAN-OLD-RAIL`, `LANDMARK-HELWAN-IRON-STEEL`) arrive `unknown` because the research does not date them — they are open gaps in the batch README — so the seed now holds **13 `unknown` entities in total**. The brief's "14 → 11" describes pre-existing entities only; those two were not promoted to make the total read 11.
- All 95 facts retain the `verification_state` supplied by the research file: **48 `verified` / 47 `single_source`**. The 48 `verified` rows were checked against the stated rule (official source, `url_check=ok`, non-null URL) and all pass; no fact was upgraded or downgraded during adaptation.
- `url_check` has no column in the evidence schema, so it is preserved inside each evidence `note` as `url_check=<ok|unchecked|unreachable>` rather than dropped. Batch split: 41 ok / 26 unchecked / 3 unreachable.
- `code_remap.json` is **informational only**. The facts already reference the canonical codes (`DIST-OLD-CAIRO`, `DIST-SAYEDA-ZEINAB`, `ROAD-AIN-SOKHNA`, `TRANSIT-BRT`, `TRANSIT-HSR-L1`, `TRANSIT-METRO-L6`, `CITY-15-MAY`), so no entity was renamed and no status or sector was changed on the strength of it.
- Conflicting values are kept **side by side**, as the README instructs, instead of being reconciled: Yasser Rizk axis 7 km vs 9 km, Kafrawy axis 4–7 vs 4–8 lanes, and South Helwan bridge 2.520 km vs 9.100 km.
- **No geometry was invented.** The 31 new entities are added without coordinates. An exact OSM name match was attempted for NMEC, Ein El Sira, Japanese Garden and Fustat Hills; where no confident match exists the geometry is left empty, and the entities still resolve in search and the entity panel.
- No new UI was added for this batch.
